## 课程简介

这是南京大学计算机学院 **蒋炎岩**（jyy）的《操作系统》（2026 年春季的课程页叫《操作系统原理》），每年春季开，讲义、视频和实验全部公开，是中文世界最受欢迎的操作系统课之一。

课程从三个视角看操作系统：

- **应用程序的视角**：操作系统定义了一组对象（进程、线程、地址空间、文件、设备……）和操纵它们的 API（系统调用）。浏览器、游戏、容器、虚拟机、调试器、甚至游戏外挂，都建立在这组 API 之上。
- **硬件的视角**：操作系统就是一个能访问全部硬件的 C 程序，加载完第一个程序后就作为“中断处理程序”在后台管理整台机器。
- **数学的视角**：计算机系统和“1 + 1 = 2”一样是良定义的数学对象，可以用函数（或代码）精确描述。

风格非常鲜明：**这是一门“编程课”**。每节课都带着“要实现一点什么”的目标，讲到任何概念，老师往往直接在命令行里写代码演示——
比如在 Linux 上复刻金山游侠、按键精灵、变速齿轮三类经典游戏外挂，拿去改真正的游戏；又比如构建操作系统的可执行模型，用形式化方法“暴力枚举”程序的所有可能行为。

注意这几年课程改版很大：**2026 年版不再讲内核怎么实现，也没有内核实验**，所有实验都是编程小实验（mini labs）。
官方的建议是：想学内核实现，就读参考书 OSTEP，或者去上 [MIT 6.1810](/docs/systems/operating-systems/mit-6-s081)。2022 年及以前的版本还保留着在自制硬件抽象层上写内核的 L 系列实验。

## 先修要求

官方的说法是：**只要会写代码就可以**。

实际上你会一直和 C 语言、Linux 命令行、gdb 打交道：官方要求准备好一个 UNIX 编程环境（Linux、macOS、Windows 上的 WSL 或虚拟机都行），
能在里面编辑、编译、调试 C/C++ 代码。学过计算机系统基础（如 [CSAPP](/docs/systems/systems-fundamentals/cmu-15-213-csapp)）会轻松很多。

## 课程结构

2026 年春季共 30 讲：

| 部分 | 讲什么 |
|---|---|
| 绪论 | 课程概述；应用视角的操作系统；硬件视角的操作系统；Scaling Law 和 Agentic AI |
| 虚拟化 | 程序和进程；进程的地址空间；访问操作系统对象；终端和 UNIX Shell；C 标准库和实现（两讲）；链接和加载；应用程序生态 |
| 并发 | 多处理器编程；互斥；同步（两讲）；并发 bug 和应对；并行算法与数据结构；异步编程模型；CPU、GPU 和 SIMT 编程模型；数据中心和并发编程 |
| 持久化 | 设备和驱动程序；持久数据的存储；文件系统 API（两讲）；文件系统实现；数据库系统；计算机系统安全；虚拟机和容器 |
| 总结 | 操作系统视角的应用程序；课程总结 |

参考书首推 **OSTEP**（《Operating Systems: Three Easy Pieces》，免费在线），老师的评价是“至今为止最好的操作系统读物，没有之一”；其次是 CSAPP。

评分：期末考试（闭卷）50%、期中随堂测验 10%、实验 40%。

## 官方作业

**九个编程小实验**（M1～M9）：

| 实验 | 内容 |
|---|---|
| M1 labyrinth | 写一个命令行下的 Rogue-like 文字冒险游戏 |
| M2 pstree | 实现 `pstree`，通过操作系统提供的接口读出进程树 |
| M3 sperf | 用进程管理 API 启动 strace 这样的跟踪工具并解析它的输出，统计程序在各个系统调用上花的时间 |
| M4 crepl | 写一个 C 语言的交互式 shell：输入的函数用 gcc 编译后加载进当前进程，表达式实时算出结果 |
| M5 mymalloc | 实现一个多处理器下的内存分配器（malloc/free） |
| M6 gpt.c | GPT-2 的并行推理（官方特意叮嘱不要参考 Karpathy 的 llm.c） |
| M7 httpd | 写一个 HTTP 服务器 |
| M8 fsrecov | 从被格式化的 FAT 文件系统镜像里把文件恢复出来 |
| M9 libkvdb | 实现一个持久化的键值数据库 |

**框架代码公开**：`git clone https://git.nju.edu.cn/jyy/os2026.git`，每个实验在各自的分支上。框架自带测试套件（testkit），本地就能跑；
提交到 Online Judge 需要选课学生才有的密钥。

**AI 政策很有意思**：官方坦率承认这些实验已经“远远低于 AI 的能力”，Coding Agent 能轻松做完。所以规则是：和操作系统无关的部分可以让 AI 生成，
但**涉及和操作系统交互的接口**，你必须自己去问 AI 系统调用怎么用，然后独立完成调用、调试、观察结果，确保真的理解程序和操作系统 API 的交互。

## 学习建议

- **跟着 B 站视频学。** 每节课都在 B 站直播，录像按学期整理成合集；课程网站上每讲的讲义里附有课上演示的代码，边看边跑。
- **实验不要让 AI 代写。** 课程自己也说了，AI 能做完这些实验，但那样你什么也学不到。至少系统调用那部分要亲手写、亲手调。
- **课后读 OSTEP。** 课上不讲内核实现，OSTEP 正好补上，而且写得有趣。
- **想写内核，去看老版本或 6.1810。** 2022 年版的 L 系列实验（物理内存管理、内核线程、用户进程、文件系统）还在网站上；MIT 6.1810 的 xv6 实验更系统。
- **浏览器会提示证书问题。** 2026-09 核对时 jyywiki.cn 的 HTTPS 证书已过期，浏览器会弹安全警告，内容本身正常。

## 同类课怎么选

- **[MIT 6.S081](/docs/systems/operating-systems/mit-6-s081)**：官方推荐的后续课，在 xv6 上写内核，和这门课的“应用视角”正好互补。
- **[UC Berkeley CS162](/docs/systems/operating-systems/cs162)**：理论覆盖全面，Pintos 项目偏设计。
- **[哈工大 操作系统](/docs/systems/operating-systems/hit-os)**：同样是中文课，围绕 Linux 0.11 的源码讲内核实现。
- **[CMU 15-213 CSAPP](/docs/systems/systems-fundamentals/cmu-15-213-csapp)**：系统编程基础，适合先修。

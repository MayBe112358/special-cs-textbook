## 简介

写一个小 C 程序，敲一行 `gcc main.c` 就编译好了。可项目一大，事情就多了：几十个源文件、几个库、
不同平台上编译器和路径都不一样、有的文件要先生成、还要跑测试、要安装。
CMake 就是来管这件事的：你用它的语言写一份 `CMakeLists.txt`，描述“这个项目由哪些目标组成、谁依赖谁、要哪些库”，
然后它替你生成当前平台上真正干活的构建系统：Linux 上是 Makefile 或 Ninja，Windows 上可以是 Visual Studio 工程。

所以 CMake 严格说不是构建工具，而是“构建系统的生成器”。
今天大多数开源 C/C++ 项目都用它，不少课程的作业也用它（比如 [AP1400-2](/docs/programming-intro/aut-ap1400) 的每一份作业）。
学会它，你至少能把别人的项目顺利编译出来；再进一步，能给自己的项目写出干净的构建配置。

写作时 CMake 的最新版本是 4.4。

## 先修要求

- 会写一点 C 或 C++，编译过、运行过程序。
- 知道编译和链接是两步、库是什么；不清楚的话，先看看 [GNU Make](/docs/essential-tools/gnu-make) 那一页。

| 你想做什么 | 看什么 |

## 官方教程与练习

- [官方 CMake Tutorial](https://cmake.org/cmake/help/latest/guide/tutorial/index.html)：CMake 自己的教程，从第 0 步（准备环境）到第 11 步，每一步都附了练习代码（教程页里有压缩包下载），做完一步能直接和下一步的起点对照：
  - 第 1–3 步：第一个 CMake 项目、CMake 语言的基础、配置和缓存变量；
  - 第 4–6 步：深入理解“目标”（target）、库的概念、探测系统环境；
  - 第 7 步：自定义命令和生成的文件；
  - 第 8 步：用 CTest 写测试；
  - 第 9 步：安装；
  - 第 10 步：查找和使用依赖；
  - 第 11 步：其他零散功能。
- [使用者指南](https://cmake.org/cmake/help/latest/guide/user-interaction/index.html)：只想编译别人的项目时看这个，讲清楚命令行和图形界面怎么用。
- [依赖管理指南](https://cmake.org/cmake/help/latest/guide/using-dependencies/index.html)：在自己的项目里引入第三方库。

## 学习建议

- **用“面向目标”的写法。** 现代 CMake 的核心是 `target_*` 系列命令：把头文件目录、编译选项、依赖都挂在具体的目标上，而不是设全局变量。网上很多老教程还在用全局写法，看到了要警惕。
- **源码目录和构建目录分开。** 永远在单独的 `build` 目录里构建（`cmake -S . -B build`），源码目录保持干净，出了问题整个删掉重来。
- **碰到报错先看是哪一步。** CMake 分“配置”（读 `CMakeLists.txt`）和“构建”（真正编译）两步，搞清楚报错发生在哪一步，问题就找到一半了。
- **拿作业练手。** 做 C/C++ 课的作业时，试着自己从零写它的 `CMakeLists.txt`，再和课程给的对比。

## 同类工具怎么选

- **[GNU Make](/docs/essential-tools/gnu-make)**：更底层，直接写规则和依赖。CMake 在 Linux 上通常就是生成 Makefile 给它跑。理解了 Make，CMake 在干什么会清楚很多。
- **Meson、Bazel 等**：其他构建系统，各有拥趸。但 C/C++ 世界里 CMake 用得最广，先学它最划算。

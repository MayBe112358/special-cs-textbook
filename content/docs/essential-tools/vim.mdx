## 简介

Vim 是一个很老、也一直很活跃的文本编辑器（写作时最新版本是 9.2）。服务器上几乎一定装着它，
很多现代编辑器（VS Code、JetBrains 系列，甚至很多浏览器插件）也都有“Vim 模式”。

它的核心不是快捷键多，而是把编辑动作设计成了一门可以组合的小语言：
一个动词（删除 `d`、修改 `c`、复制 `y`）加一个范围（一个词 `w`、到行尾 `$`、括号里面 `i(`），
比如 `dw` 删一个词、`ci(` 改括号里的内容。零件不多，组合起来的命令却多得多，而且学会一个新范围，所有动词就都能配着用。

另一个特点是“模式”：在普通模式下，按键是命令而不是打字。这是初学者最容易卡住的地方（包括那个著名的“怎么退出 Vim”），
也恰恰是它高效的来源：写程序的时候，你大部分时间其实不是在打新字，而是在移动光标、改已有的代码。

## 先修要求

- 会在终端里打开一个程序、退出一个程序。
- 先记住一条就够了：不管在哪个模式里乱了，按几下 `Esc` 回到普通模式，再敲 `:q!` 回车，就能不保存退出。

## 学习路线

以 Vim 自带的文档为主线：

| 阶段 | 学什么 | 官方材料 |
|---|---|---|
| 第一天 | 模式、移动、插入、删除、保存退出 | `vimtutor`：Vim 自带的 30 分钟交互教程 |
| 第一周 | 更多移动方式、小改动、设置、多文件、分屏 | 用户手册第 2–8 章 |
| 熟练 | 大改动、重复操作（`.`、宏）、搜索与替换、折叠、写代码时的移动 | 用户手册第 10、20–30 章 |
| 定制 | 配置文件、写自己的命令、Vim 脚本、插件 | 用户手册第 40–52 章 |

## 官方教程与练习

Vim 是工具，没有“作业”；最好的练习就是把它用在每天真正的工作里。几份官方材料按顺序来：

- **vimtutor**：装好 Vim 后，在终端里敲 `vimtutor`（Windows 上在开始菜单的 Vim 目录里）。它会打开一份可以边读边改的教程文件，两章，官方说大约 30 分钟。第一次学一定从这里开始。
- [Vim 用户手册](https://vimhelp.org/usr_toc.txt.html)：`:help user-manual` 能在 Vim 里打开同样的内容，按“从入门到定制”的顺序写成，比参考手册好读得多。
- [Missing Semester 的开发环境一讲](https://missing.csail.mit.edu/2026/development-environment/)：讲模式化编辑的思路，讲义末尾的练习很实在：接下来一个月，在所有支持 Vim 模式的软件里都开着它，觉得哪里别扭就去查有没有更好的办法。

## 学习建议

- **先忍一周。** 刚换到 Vim 的头几天会比以前慢，这很正常。坚持用一周，常用的移动和修改就会变成手指的记忆。
- **一次只加一个新招。** 别想着一口气背完所有命令。觉得某个操作重复了三遍，就去 `:help` 里查有没有更短的办法，学会了再加下一个。
- **学会查帮助。** `:help 命令` 能跳到任何命令的说明，`:help` 里的链接可以用 `Ctrl-]` 跳过去。会查帮助，就不用背。
- **不一定要换编辑器。** 如果你已经习惯 VS Code，装一个 Vim 插件就能享受大部分好处；服务器上临时改个配置文件时，再用原版 Vim。
- **Neovim 也很好。** 它是 Vim 的一个现代分支，默认设置更友好、插件生态活跃，基本操作和 Vim 完全一样。

## 同类工具怎么选

- **[Emacs](/docs/essential-tools/emacs)**：另一个历史悠久的编辑器，思路完全不同：用组合键（Ctrl、Alt）而不是模式，可以用 Lisp 把它扩展成几乎任何东西。
- **VS Code 这类图形编辑器**：上手最容易，插件多。和 Vim 并不冲突，装个 Vim 插件，两边的好处都能要。
- 真正要不要学 Vim？至少要会最基本的操作：总有一天你会登进一台只有 Vim 的服务器。

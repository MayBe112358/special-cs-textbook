# 一本特殊的 CS 教材

在线地址：<https://maybe112358.github.io/special-cs-textbook/>

这个网站有两层内容，互相指着对方：

- **课程是目录**。按知识领域组织的计算机科学课程树，每门课只写简介、先修要求和官方链接，
  练习一律指向课程团队自己发布的作业，站内不自编习题。
- **代码是正文**。这个网站自己的源码就是教材正文，讲解写在每个核心文件顶部的结构化注释里，
  由构建脚本抽取成 `internals` 分支下的讲解页。

两层之间的跳转是自动的：课程页底部列出“学完这门课可以读哪些代码”，讲解页顶部列出“读懂这里
需要先学哪些课”。这些链接由源码注释里的 `@courses` 字段生成，改注释就会改链接。

网站是纯静态的，同一棵树有两个入口：左边的侧边栏，和底部的终端。

## 工作区

打开网站先看到首页：一段可以直接点的演示终端，和“接着上次学”的入口。进到里面是一个像 VS Code 的工作区：

- **左侧活动栏**只有三块：**课程目录**（`/docs`）、**学习路径**（`/paths`）、**个人心得**（`/notes`）。
  点当前那块的图标会收起侧边栏。
- **标签页**：单击侧边栏打开的是斜体的“预览标签”，下一次单击会替换它；双击标签或开始编辑就固定下来。
  标签能拖动换位置；右键有「关闭其他 / 关闭右侧 / 关闭已保存的」；有未保存修改的标签显示圆点，关闭前会问。
  刷新后标签还在。手机上标签收成顶栏里的一个下拉列表。
- **终端**贴在底部，在三块之间切换时命令历史不丢。
- **AI 助手**：活动栏最下面的图标（或 `Ctrl+Alt+I`），侧边栏换成对话框；终端里敲 `agent` 也能对话。详见下面「AI 助手」。

## 终端

页面底部可以展开一个终端。走动和查看的命令对齐真实 Unix；进度、反查和搜索是本站自己的命令，
命名同样是小写、简短的动词。

| 命令 | 作用 |
|---|---|
| `ls` | 列出当前位置下有什么，每一项可以点 |
| `cd` | 切换位置，支持 `..`、`~`、`-` |
| `pwd` | 显示当前位置 |
| `tree` | 可折叠的目录树 |
| `cat` | 在终端里读一门课的简介或一个模块的讲解 |
| `open` | 在正文区打开对应页面 |
| `refs` | 课程 ↔ 代码互相反查 |
| `find` | 按名字、类型、学习状态或先修课筛选 |
| `grep` | 筛选上一条命令的结果，或筛选简介 |
| `search` | 用中文或英文搜索课程和代码讲解 |
| `mark` | 标一门课的学习状态，或标一段代码的理解度 |
| `status` | 查看上述标记；不带参数时给出整体统计 |
| `history` | 查看这次打开页面后敲过的命令 |
| `clear` | 清屏，命令历史仍可用方向键翻回 |
| `help` | 列出全部命令 |
| `agent` | 和 AI 助手对话：`agent` 进入对话（`exit` 退出），`agent 问题` 只问一句，`agent -c` 接着上一段 |

打到一半按 Tab：只有一个候选时补全命令名或路径，有多个候选时只列出来。`↑` `↓` 翻历史。
管道把前一条命令的结构化结果交给后一条，例如 `find / -type f -name 'cs*' | grep -i CS61A`。

终端不自己保存“当前目录”——位置完全由网址推导，因此鼠标点侧边栏和终端里 `cd` 始终同步，
浏览器的前进后退和分享网址也都正常。

## 进度与理解度

课程和代码是两条分开的进度线。你自己的标记存在浏览器里：

- 课程页可以标成「想学 / 在学 / 学完」，终端里对应 `todo` / `learning` / `done`。
- 讲解页可以标成「未读 / 读过 / 读懂了」，终端里对应 `unread` / `read` / `understood`。
  整体理解度只计算标成「读懂了」的模块。
- 作者自己的进度写在内容文件里，人人可见，和你的标记互不影响。清空浏览器数据不会改动作者进度。

`mark cs61a learning` 标一门课，`mark <模块> understood` 标一段代码，加上 `clear` 则清掉该标记。
`status` 不带参数时同时报告两条线。

## 学习路径

「学习路径」这一块里，每条路径是一张导图：从左边的课程树把课程拖到画布上变成方块，再从方块边上拖出箭头连成路线；
也可以在工具栏里搜课程添加。“整理布局”按先修关系自动排好（先修在左、后续在右）。可以有多条路径并切换，
一门课可以同时出现在多条路径里。手机上只能看，不能编辑。

路径存在本机。作者按 learncs.site 整理的那一条只是示例，复制之后才成为你的路线，之后与示例互不影响。
课程数据里没有写死任何学习顺序。旧版“按顺序排列”的路径会自动转换成一串用箭头连起来的方块。

## 个人心得

「个人心得」左边是一棵和课程目录一样的树，每门课一个心得空间；写过心得的课，名字后面会显示有几份。
在一个空间里可以：

- 新建 Markdown 文档：支持代码高亮、`$数学公式$`、表格，`Ctrl+S` 保存；没保存就切走，草稿会暂存下来。
- 导入本地的 `.md` 和常见代码文件（选择或直接拖进来），打开时按语言着色。图片等二进制文件不收。
- 新建导图：双击空白处加方块，拖动、连箭头、`Delete` 删除、`Ctrl+Z` 撤销，自动保存。
- 改名、删除，或者把一份心得**移动**到另一门课下面。

作者的心得（`content/author-notes.json`）显示在对应空间的最上面，只读，和你自己的分得清。

## AI 助手

读者自己选模型厂商、填自己的 API Key，AI 就能读这个网站里属于读者的东西（心得文档、导图、学习路径、学习状态）
和教材本身（课程简介、先修、源码讲解），帮忙答疑、写心得、画导图、起草学习路线。

- **两个入口**：左侧活动栏最下面的 AI 图标（侧边栏换成对话框，正文不动）；终端里的 `agent`
  （进入对话模式，`exit` 退出；`agent 问题` 只问一句；`agent -c` 接着上一段）。
- **厂商**：Anthropic（Claude）、OpenAI、DeepSeek、通义千问、智谱 GLM、MiniMax 可以直接从浏览器调用；
  Kimi 和 Gemini 不允许网页直接调用（跨域限制），需要填自己的转发地址；也可以填任意兼容 OpenAI 或 Anthropic 接口的地址。
  厂商资料参考了 [cc-switch](https://github.com/farion1231/cc-switch)，但“用哪种接口格式”按浏览器实测能否直连来定。
- **Key 只存在你的浏览器里**（localStorage），请求由浏览器直接发给厂商，不经过这个网站，也不进备份文件。
  请在厂商后台给 Key 设额度上限。
- **模型和权限在聊天框底部选**，跟着每一段对话走：模型菜单列出填好 Key 的厂商的模型（最近用过的在前）；
  权限三档——**只读**（AI 拿不到任何改动工具）、**每次确认**（默认：先给你看改前 / 改后，同意才写入）、**自动同意**（直接写入，对话里列出改了什么）。
  写入前都会核对内容有没有在 AI 读过之后被你改过，改过就作废。AI 不能删除任何东西。
- **对话有历史记录**：存在浏览器里（IndexedDB），按日期分组、可搜索、改名、删除，点开接着聊，模型和权限一起恢复；
  终端里的对话也在里面（标注“终端”），`agent -c` 接着最近一段聊。导出备份时可以勾选“包含 AI 对话记录”（默认不带）。
- Claude 官方接口上默认打开提示缓存、工具参数流式传输和拒答时的服务器端自动换模型（`fallbacks: "default"`）。

代码在 `core/assistant/`（和界面无关，带测试）和 `components/assistant/`。

## 搜索与先修关系

- 页面上的搜索框，以及终端里的 `search`，都在浏览器里查询同一份索引，中文和英文都能搜到课程和代码讲解。
  网站仍然没有搜索服务端。
- 每门课的先修课写在课程页的 `prereqCourses` 字段里，课程页的「先修要求」一栏用文字说明。
  终端里 `find` 能按先修课筛选，学习路径的“整理布局”也按这份关系排方块。
  （阶段 12 的独立知识图谱页已在阶段 14.5 删除。）

## 排版

课程页（`content/docs/` 里的 MDX）可以写数学公式、带语法颜色的代码块，以及 mermaid 流程图。
公式和代码颜色在构建时生成；流程图在浏览器里绘制，会比正文稍晚出现，并跟随深色或浅色主题。
源码讲解页里的例子块照原样显示，不上颜色：它们多是终端命令和报错，按某种语言去着色只会涂错。
公式和流程图目前只在课程页里可用。

## 本地运行

```powershell
npm install
npm run dev
```

浏览器打开 <http://localhost:3000>。

其他命令：

```powershell
npm run index   # 重新扫描内容与源码注释，生成知识索引
npm test                # 跑命令引擎、文件系统、进度、路径、心得、搜索与备份的测试
npm run check:letters   # 检查每个源码文件顶部都有完整的注释块
npm run build           # 类型检查并静态导出到 out/
```

`npm run dev`、`npm test` 和 `npm run build` 都会先自动跑一次 `npm run index`。

推送到 GitHub 后，Actions 会自动跑测试、注释块检查和构建（`.github/workflows/check.yml`）；
推到 `main` 时检查通过才会部署到 GitHub Pages（`.github/workflows/deploy-pages.yml`）。

## 目录

| 位置 | 放什么 |
|---|---|
| `content/docs/` | 课程页（MDX），目录名用英文，中文标题写在文件里 |
| `core/` | 与界面无关的纯逻辑：命令引擎、虚拟文件系统、知识索引、搜索、进度、心得条目、导图、统一编辑接口、AI 助手（厂商、工具、对话循环） |
| `components/` | 界面：工作区（活动栏、标签页）、AI 助手面板与设置、终端、心得、导图画布、评论、进度、学习路径、搜索、讲解页、首页 |
| `app/`、`lib/` | Next.js 与 Fumadocs 的接线；`app/(workbench)/` 是三块共用外壳的路由组 |
| `scripts/` | 构建期脚本：生成知识索引、修补静态预取、检查注释块 |
| `开发指导文档/` | 项目定位、协作约束与分阶段规划 |

## 数据存在哪

- **你的东西都在你自己的浏览器里**：学习状态和理解度在 localStorage，心得、导入的文件、导图和学习路径在 IndexedDB。
  换一台设备看不到。心得首页可以导出一个 JSON 备份，一次带走全部内容，在别的浏览器里再导入；旧版本的备份也能导入。
- **作者的进度和心得**写在内容文件里，跟项目走，任何人都能看到，和你的数据互不影响。
- **公开评论**在课程页底部，用 GitHub Discussions（Giscus），需要 GitHub 账号，网站本身依然没有服务端。

## 一、一句话概括

**这是一本特殊的计算机科学教材。**

它长得像一个终端风格的文档网站，但它的身份不是网站，是教材。

---

## 二、教材的三个部分（理解全篇的钥匙）

一本普通教材有目录、正文、习题。这本教材的对应关系是：

| 教材的部分 | 在这个项目里是什么 |
|---|---|
| **目录** | 网站里展示的课程体系（按 csdiy.wiki 的分类组织） |
| **正文** | **项目自己的源代码，以及代码里的注释** |
| **习题** | 各门课**官方**的 lab / project / problem set |

三条推论，是很多规矩的源头：

**课程页面内容可以很少。**只放简介、官方资源链接、官方作业链接就够了。
看到某一页是空的，那是预期状态，不是待办事项。

**真正的讲解写在代码注释里。**读者学完一门课，回头读项目里对应的那部分代码，
读懂了，这一课才算学完。所以注释不是代码的附属说明，注释是正文。

**习题不自己编。**官方作业有完整框架和保姆级说明，质量远高于自编题。
项目要做的是把它们组织好、链接好，不是重新发明。

判断一个功能该不该做，可以问：**它让「目录 → 正文 → 习题」这三者的连接更紧密了吗？**

## 三、注释为什么要写成一封信

规矩本身见 `AGENTS.md` 第 1 节。这里讲为什么。

注释的收信人是**未来那个学完了这门课、回过头来读这段代码的人**——
可能是作者自己，也可能是任何一个 fork 走这个项目的自学者。

**信的语气不是装饰，是这本教材的教学法。**

普通教材给的是整理干净的结论："此处采用递归下降解析以处理运算符优先级。"
这封信给的是一条真实的认知路径："写这段时我还没学到这里，AI 说要分成两步才能处理优先级，
你现在学完 CS61A 了，回头看看它说得对不对。"

对一个自学者来说，后者往往更有用——因为他很可能正卡在同一个地方。
一条"有人也曾经不懂，这是他当时的处境"的记录，比一个完美的结论更能让人走下去。

**诚实标注不懂的地方，因此不是缺陷，是这本教材的内容来源。**
那些 `@unclear` 的位置，正是将来最该被补上的章节。

同时它必须是一本零基础也读得下去的教材——语气像信，深度像教材，前提是收信人什么都还不会。
这两者不冲突：信本来就是写给一个不懂的人看的。

## 四、读者是谁

**任何人，包括零基础的自学者。**项目开源，别人 fork 走也要能学。

由此推出两条：作者本人只是这本教材的读者之一；
**作者当前的自学进度不是这个项目的设计约束**——不要因为"作者学到哪"就调整深度或范围。

---

## 五、作者的角色：全程 vibecoding

**作者不写项目代码，全部由 AI 完成。**这是明确的、经过考虑的决定，不是暂时的妥协。

作者负责的是：方向、取舍、内容范围、这本教材要教什么。

作者会经常问"这段在干嘛""这个报错什么意思"——这是项目的正常流程，
而且这些提问的答案本身就是教材素材，回答完顺手写进注释即可。

## 六、课程体系为什么是一棵树而不是一条线

结构规则见 `AGENTS.md` 第 2 节。这里讲理由。

课程目录按 **CS自学指南（csdiy.wiki）** 的分类组织，形态像那个网站的侧边栏，
同一分支下并存多所学校的同类课程（操作系统那一支就有好几套）。
保留这种并存是有意的：不同学校的侧重点和实验不同，读者可以按需要挑。

**项目提供的是这棵树，不是一条路线。**

理由很简单：路线是个人的。读者读完课程介绍自己决定学什么、按什么顺序学，
这件事项目不该替他做。所以路径属于访问者自己的数据，不是项目内容的一部分。

作者本人目前选的是 CS自学社区（learncs.site）课程资源那一条
（CS50x → CS61A/B/C → …，配 MIT 18.01 / 18.02 / 18.06 / 6.042J）。
这只是**作者的个人选择**，可以作为示例展示，但不是默认路线，也不是课程目录的边界。

**注释里标课程对应时同理**——不要只标作者在学的那几门。
一段代码如果同时和 CS61A、MIT 6.828、Stanford CS143 有关，就都标上，
读者不管沿哪条自建路径走过来，都应该能找到对应的代码。

## 七、网站的形态与终端的意义

界面是开发者工具 / IDE 风格的文档站：左边课程树，中间正文，右边页内目录，底部可折叠的终端。

视觉方向是**现代 IDE 和终端产品**，不是"黑底绿字"那种刻板黑客风。
正文必须保持正常文档的可读性——不能为了终端风格牺牲长文阅读体验，这是硬要求。

### 为什么终端不是装饰

鼠标和终端两套操作地位相同、共享同一套数据。但终端要挣到自己的位置，标准是：

> **它能不能做鼠标做不到的事。**

`cd` 进目录这类操作鼠标本来更快，做到能用即可。
真正的理由在跨课程按前置关系反查、按状态筛选、多命令组合查询——侧边栏永远做不到这些。

### 为什么命令要严格对齐真 Unix

包括报错信息照抄、不做"你是不是想输入 xxx"的自动纠正。

因为读者在这里养成的习惯将来会迁移到真终端——**这本身就是教材的一部分**
（对应 csdiy.wiki「必学工具」那一章）。自造的方便语法是负资产；
自动纠正会让人放松，而放松学不会命令行。

首页那个演示终端反过来要极度友善（有提示、有可点的示例、`help` 一目了然）——
同一个内核，两种默认友善度。

### 心得系统为什么要能导出

访问者的心得默认存在他自己的浏览器里，而浏览器数据太容易丢——清缓存、换设备就没了。
所以导出不是锦上添花，是必需品。

更进一步：如果心得能导出成可以提交回项目的格式，别人 fork 之后就能把这个项目
变成**他自己的那本教材**。这是这个项目最漂亮的一种可能性，而成本很低。

## 八、几个关键技术决定的理由

规则条文见 `AGENTS.md` 第 7、9 节。这里只讲为什么。

**为什么不用 xterm.js**
它是给真实终端用的，本项目不接真实 shell，用不上它的核心能力，
反而受限于"输出只能是纯文本"。而这里需要 `ls` 每一项可点击、进度条是真进度条、
目录树能折叠、代码块能高亮——用普通网页组件实现更简单也更好看。

**为什么页面地址是唯一真相**
终端和鼠标如果互相通知，就会出现循环和不一致。
让两边都读同一个地址，一致性是天然的，不需要写同步逻辑。

**为什么命令引擎必须和框架无关**
一是可测——脱离浏览器就能验证；二是它对应 CS61A 的解释器、编译原理这些课程，
**是教材里最重要的一章**，混进框架代码会让它变得没法讲。

**为什么第一版做纯静态**
第一版的功能不需要服务端，纯静态链路最短、最不容易出问题。
公开评论用 GitHub Discussions 方案（Giscus）依然是纯静态。
真需要账号 / 云同步 / AI 问答时再迁，改配置即可，不用重写。

## 九、课程与代码的对应关系（教材的知识地图）

注释和讲解页要尽量把这些写全，且不限于任何一条路径：

| 项目模块 | 可对应的课程 |
|---|---|
| 命令解析（拆词、语法分析、求值） | CS61A（解释器）、Stanford CS143、UCB CS164 |
| 虚拟文件系统、路径解析、目录树 | CS61B（树与图）、MIT 6.828 / CS162（文件系统） |
| 知识图谱、依赖排序 | CS61B、MIT 6.042J（离散数学） |
| 索引构建与查询、筛选 | CMU 15-445、CS186 |
| 状态管理、数据流 | 软件工程类课程 |
| Git、终端、编辑器、构建工具的使用 | csdiy.wiki「必学工具」一章 |
| 前端框架、渲染、部署 | 不对应传统 CS 课程 → **这正是这本教材的独有价值** |

最后一行值得强调：Web 工程那一大块在任何 CS 课程体系里都是空白，
而这个项目本身就是一个真实的 Web 工程案例。
**把它讲清楚，是这本教材相对其他自学资源的增量。**

数学线基本不参与代码对应，它在这里是**被组织的内容，不是被使用的工具**，不必勉强去缝。

## 十、最大的风险：配比

不是技术，是注意力分配。

项目有两个方向：**做工具**（终端、命令、图表，每天都有正反馈）和
**写教材**（注释、讲解页、课程组织，见效慢）。注意力会自动流向前者。

最可能的失败形态：**终端打磨得极其精致，点进去每一页都是空的、代码里一行注释没有。**

判断标准很简单：如果在加第八个命令，而注释系统、跳转链路、心得系统还没打通，就是走偏了。

（`AGENTS.md` 第 10 节的优先级规则，就是这条风险的具体化。）

## 十一、给接手对话的 AI 的提醒

1. **项目代码就是教材正文**，注释是一封写给未来读者的信——语气像信，深度像教材，假设收信人零基础。
2. **课程页面内容少是正常的**，不要提醒补内容。
3. **习题一律用课程官方的**，不要自己编题。
4. **课程目录是一棵树，项目不内置学习路径**——路径由使用者自己组。
5. **注释里的课程对应要尽量列全**，不限于作者当前在学的课。
6. **不要劝作者自己写代码**，也不要留"以后自己重写"的坑。全程 vibecoding 是设计前提。
7. **不要因为作者基础不深就降低教材深度**，读者是所有人。
8. **解释代码时用大白话**，术语当场解释——反正这些解释最后都要进注释。
9. **具体怎么做，一律看 `AGENTS.md`；做到哪一步、怎么验收，看 `ROADMAP.md`。**

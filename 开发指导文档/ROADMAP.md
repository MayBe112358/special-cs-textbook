# ROADMAP.md — 从零到 1.0 的完成规划与验收标准

> 用途有两个：
> 1. 让 AI 知道**现在该做哪一步、这一步做到哪里为止**
> 2. 让作者知道**这次 coding 算不算合格**
>
> | 文档 | 回答什么 | 什么时候读 |
> |---|---|---|
> | `PROJECT.md` | **为什么**——定位、理念、风险 | 开新对话时读一次 |
> | `AGENTS.md` | **做什么 / 不做什么**——所有规矩 | 每次 coding 都读 |
> | **ROADMAP.md**（本文） | **什么时候做、怎么算合格** | 每次 coding 都读 |
>
> 阶段划分和验收标准以本文为准；规矩以 `AGENTS.md` 为准。本文不重复规矩条文。
>
> **使用方式**：每次开始 coding，先说"现在做第 X 步"。AI 只做那一步，不许往前跑。

---

# 第一部分：通用验收法（最重要，先读这里）

vibecoding 最难的不是让 AI 写代码，是**判断它写的到底成没成**。
下面这套方法对任何一步都适用。

## 1. 每一步开始前，先问 AI 要"验收条件"

固定话术：

> "这一步做完之后，我应该看到什么？请在动手前先告诉我验收标准，
> 用我能亲眼确认的方式描述，不要说代码层面的事。"

**AI 说不出可验证的现象，说明这一步定得太模糊或太大，先拆。**

好的验收条件长这样：
- "浏览器打开首页，左边能看到一棵树，点『系统』能展开出四个子项"
- "在终端输入 `ls` 回车，下面出现一列文字，每一项能点，点了跳到对应页面"

坏的验收条件长这样：
- "索引构建完成" / "架构分层清晰" / "类型定义完善" ← 你没法验证，不接受

## 2. 收尾三问（每次必过）

**问一：我亲眼看到它成了吗？**
不是 AI 说"完成了"，是你自己打开浏览器点了一遍。看不见的功能见下面第 4 条。

**问二：以前能用的东西还能用吗？**
过一遍下面的「回归清单」。AI 改新功能时弄坏旧功能，是最常见也最难发现的问题。

**问三：注释补了吗？**
新写的核心文件有没有 `@letter` 那一段？没有就让它补完再存档。
`AGENTS.md` 里这是硬规矩，但它最容易被跳过。

## 3. 回归清单（每次改完都过一遍，两分钟）

1. 网站能正常打开，没有白屏、没有报错弹窗
2. 侧边栏能点开、能收起
3. 随便点进一个课程页，正文能正常显示
4. 终端能打开、能输入、能回车
5. 之前做过的每个命令各敲一次，输出正常
6. 刷新页面，一切正常

**任何一条不过 → 这次 coding 不合格，先修，不要往下做。**

## 4. 看不见的功能怎么验收

有几步（比如索引、虚拟文件系统）做完之后界面上什么都看不出来。
这类步骤必须**要求 AI 造一个临时的可见出口**：

> "这一步的结果我在界面上看不到。请加一个临时页面（或临时命令），
> 把结果直接显示出来给我看，我确认完再删掉。"

**没有可见出口的步骤，一律不算完成。**不要接受"你放心，它跑通了"。

## 5. 危险信号（出现就叫停）

| 信号 | 为什么危险 | 怎么办 |
|---|---|---|
| 一次改了十几个文件 | 出问题无法定位 | 退回上一个存档，要求拆成小步重做 |
| "我顺便优化了一下……" | `AGENTS.md` 明令禁止 | 让它撤销优化，只保留要求的改动 |
| "先装个 XX 库" | 没商量过的新依赖 | 问为什么，非必要就拒绝 |
| 让你手动改一堆配置文件 | 通常是方案走偏了 | 让它换个不需要手改的做法 |
| 报错反复修不好，越修越乱 | 已经陷进去了 | **退回上一个存档，换个思路重来**，别硬扛 |
| 界面突然变漂亮了 | 第一版禁止美化 | 让它撤销 |

## 6. 存档纪律

**每通过一次验收就提交一次**，提交信息写清这次做了什么。

理由很实际：AI 有时会把好好的东西改坏，而你当下看不出坏在哪。
有存档能一秒退回，没有就只能重来。

不熟这个操作就让 AI 教你三条命令，够用一整年。

# 第二部分：分阶段规划

每一步的格式：**目标 / 做到哪里为止 / 验收清单 / 常见翻车**

---

## 阶段 0：地基（约 2～3 次 coding）

### 步骤 0.1　建仓库、放文档

**目标**：GitHub 上有一个空仓库，里面躺着三份文档。

**做到哪为止**：只放 `PROJECT.md`、`AGENTS.md`、`ROADMAP.md`、`README.md`（占位即可）、`LICENSE`。不写任何代码。

**验收清单**
- [ ] GitHub 上能打开这个仓库
- [ ] 三份文档都在，内容完整
- [ ] 本地电脑上有一份仓库副本，能提交、能推上去

---

### 步骤 0.2　跑通一个最小网站

**目标**：本地能打开一个显示"Hello"的网页。

**做到哪为止**：一个能跑起来的空项目，首页只有一行字。**不要装 Fumadocs，不要做任何界面。**

**验收清单**
- [ ] 终端里执行一条命令，浏览器打开某个地址，看到那行字
- [ ] 改掉那行字，保存，浏览器自动变了
- [ ] AI 告诉了你这条启动命令是什么，你自己独立敲一遍成功

**常见翻车**：AI 一上来把整套技术栈都装好、目录建了二十个。
**这不合格**——第一步只要"能跑"，越少越好。

---

### 步骤 0.3　打通部署

**目标**：这个"Hello"页面能在互联网上被访问到。

**做到哪为止**：纯静态导出 + GitHub Pages 自动部署。改一行字推上去，网站自动更新。

**验收清单**
- [ ] 有一个公开网址，手机流量下也能打开
- [ ] 改一行字，提交推送，等几分钟后网址上的内容变了
- [ ] 你知道去哪里看部署有没有成功（GitHub 的 Actions 页面）

**为什么这么早做部署**：越晚接部署，积累的问题越多、越难查。
现在只有一行字，出问题一眼就能看出来。

---

## 阶段 1：文档站骨架（约 3～4 次 coding）

### 步骤 1.1　接入文档框架

**目标**：一个正常的三栏文档站：左边目录、中间正文、右边页内导航。

**做到哪为止**：接入 Fumadocs，用它的默认样式，放两三个手写的假页面。**不碰配色、不碰字体。**

**验收清单**
- [ ] 左边有侧边栏，能点，点了跳到对应页面
- [ ] 中间正文正常显示标题、段落、列表、代码块
- [ ] 右边有本页小标题的导航，点了能跳到对应位置
- [ ] 手机上打开不至于乱掉（能读就行，先不要求好看）

---

### 步骤 1.2　建课程树的目录结构

**目标**：内容目录按 csdiy.wiki 的分类组织起来。

**做到哪为止**：建出分类目录（必学工具 / 编程入门 / 数学基础 / 数据结构与算法 / 系统 / AI 与机器学习 / 理论计算机……），每个分类下**先只放一门课**作为样板。

**验收清单**
- [ ] 侧边栏显示出这棵分类树，能展开收起
- [ ] 每个分类下至少能点进一门课
- [ ] **目录名是英文**，中文标题写在文件内容里
- [ ] 系统那一支下面能放多所学校的同类课（哪怕现在只有一个），结构上没写死

---

### 步骤 1.3　定下课程页的标准格式

**目标**：一门课的页面应该长什么样，定死。

**做到哪为止**：写一门课（建议 CS61A）作为**样板页**，包含：课程简介、先修要求、官方资源链接、官方作业链接、（留空的）对应项目模块一栏。

**验收清单**
- [ ] 这一页你自己看着舒服，觉得"其他课都照这个写就行"
- [ ] 官方链接点得开
- [ ] **没有自编习题**，练习部分全是指向官方作业的链接
- [ ] 页面上没有大段自写讲解——正文在代码注释里，这里只是目录

---

## 阶段 2：数据层（约 3～4 次 coding，全程看不见）

> ⚠️ 这一阶段界面上几乎没有变化，**必须用「临时可见出口」验收**（见通用验收法第 4 条）。

### 步骤 2.1　知识索引

**目标**：构建时扫描所有内容文件，生成一份统一的 JSON。

**做到哪为止**：只扫描课程页面的基本信息（id、标题、路径、所属分类、先修）。**先不扫代码注释。**

**验收清单**
- [ ] 要求 AI 加一个临时页面，把生成的 JSON 显示出来
- [ ] 你打开这个页面，看到每门课都在里面，信息正确
- [ ] 新增一门课的文件，重新跑一次，它自动出现在 JSON 里（**这条最关键**）
- [ ] 确认完让 AI 删掉这个临时页面

---

### 步骤 2.2　虚拟文件系统

**目标**：把知识索引变成一棵"可以用路径访问"的树。

**做到哪为止**：能根据一个路径字符串找到对应的内容；支持 `..`、`~`、相对路径。

**验收清单**
- [ ] 临时页面上能输入一个路径，显示"这个路径存在吗、里面有什么"
- [ ] 试这几个：`/`、`/systems`、`/systems/operating-systems`、`/systems/operating-systems/..`、`~`、不存在的路径
- [ ] 不存在的路径返回明确的"找不到"，不是白屏或崩溃

---

### 步骤 2.3　命令引擎骨架

**目标**：一个纯逻辑模块——输入一行字符串，输出一组结果对象。

**做到哪为止**：只做一个 `help` 命令。**先不做四个命令，先把引擎跑通。**

**验收清单**
- [ ] 临时页面上输入 `help`，返回一组结构化结果
- [ ] 输入 `asdfgh`，返回 `command not found: asdfgh`（照抄 Unix 的写法）
- [ ] 让 AI 确认：这个模块里没有引用 React / Next / 浏览器 API
- [ ] 让 AI 展示测试跑过了（这块是教材最重要的一章，值得有测试）

**这一步的注释要求最高。**它对应 CS61A 的解释器项目，是教材核心章节。
`@letter` 那段要写透：为什么要把命令引擎和界面分开、不分开会怎样。

## 阶段 3：终端上线 → **第一版完成**（约 4～5 次 coding）

### 步骤 3.1　终端的壳

**目标**：页面底部有一个可折叠的终端，能打字、能回车、能显示历史。

**做到哪为止**：只有输入和回显，接上 `help`。**不用 xterm.js。**

**验收清单**
- [ ] 底部有个终端，能展开收起
- [ ] 能打字，回车后输入的内容出现在上方
- [ ] 输入 `help` 有正常输出
- [ ] `↑` `↓` 能翻之前输过的命令
- [ ] 输出多了会自动滚到最下面
- [ ] 折叠再展开，之前的内容还在

---

### 步骤 3.2　`ls` 和 `cd`

**目标**：能在课程树里走动。

**验收清单**
- [ ] `ls` 列出当前位置下有什么
- [ ] `cd systems` 能进去，提示符跟着变
- [ ] `cd ..` 能回上一层，`cd ~` 回根目录，`cd -` 回上次的位置
- [ ] `cd 不存在的东西` 报 `cd: no such file or directory: xxx`
- [ ] **没有"你是不是想输入 xxx"这种提示**（`AGENTS.md` 明令禁止）

---

### 步骤 3.3　`cat` 和 `open`

**目标**：能看内容、能跳页面。

**验收清单**
- [ ] `cat cs61a` 在终端里显示这门课的简介
- [ ] `open cs61a` 中间正文区跳到这门课的页面
- [ ] `ls` 的输出**每一项可以点**，点了等于 `open`
- [ ] 对着一个分类用 `cat` 会给出合理提示（类似 Unix 对目录 cat 的反应）

---

### 步骤 3.4　两边打通

**目标**：终端和鼠标是同一个东西的两个面。

**验收清单**（这是第一版最关键的一关）
- [ ] 鼠标点侧边栏进入某门课，**终端提示符自动变成那个位置**
- [ ] 终端里 `cd` 到某处，**侧边栏自动展开并高亮那一项**
- [ ] 浏览器的前进/后退按钮正常工作
- [ ] 复制当前网址，新开一个标签页粘贴打开，位置一致、终端提示符一致
- [ ] 让 AI 确认：终端**没有自己存一份"当前目录"**，一切从网址推导

---

### 🏁 里程碑：第一版完成

**整体验收**（全部通过才算）
- [ ] 公开网址上能访问，手机能打开
- [ ] 陌生人打开首页，不碰终端也能正常浏览课程
- [ ] 四个命令 `ls` `cd` `cat` `open` 全部可用
- [ ] 终端和鼠标完全同步
- [ ] 每个核心文件都有 `@letter` 注释块
- [ ] 回归清单全过

## 阶段 4：自用验证期（**不写代码**，1～2 周）

**这是整个项目最重要的一步，不要跳过。**

**要做的事**：把网站当自己的常用工具用一段时间。想找某门课的资料，就打开它。

**要观察的**（诚实回答，不要骗自己）：
- 你打开终端了吗？还是一直在点侧边栏？
- 敲命令的时候是觉得快，还是觉得麻烦？
- 有没有哪一刻你想"这里要是有个 XX 命令就好了"？

**结论只有两种**：

- **终端确实好用** → 按原计划继续
- **你几乎没用过终端** → 核心假设有问题。此时调整成本几乎为零，
  可以考虑把终端降级为辅助功能，把重心移到教材内容和跳转上。
  **这个发现是有价值的，不是失败。**

## 阶段 5：教材闭环（约 4～5 次 coding）— 第一版之后最重要的阶段

### 步骤 5.1　注释块被扫进索引

**目标**：源码里的 `@letter` 那套注释块，能被程序读到。

**验收清单**
- [ ] 临时页面上能看到所有注释块被解析出来的结果
- [ ] `@courses`、`@exercises`、`@prereq` 这些字段都正确提取
- [ ] 新写一个带注释块的文件，重新构建后它自动出现

### 步骤 5.2　代码讲解页

**目标**：每个核心模块有一页正式讲解，可以被访问、可以 `cat`。

**验收清单**
- [ ] 侧边栏多了一个分支（比如 `internals`），能点进去
- [ ] 每一页显示：解决什么问题、为什么这样设计、对应哪些课、去做哪个官方 lab
- [ ] 终端里 `cd internals` `ls` `cat` 都正常
- [ ] **随便挑一页给一个完全不懂编程的人看，问他"看得下去吗"**

### 步骤 5.3　双向跳转

**目标**：课程 ↔ 代码互相能找到对方。

**验收清单**（教材闭环是否合上，看这一条）
- [ ] 打开 CS61A 页面，能看到"本课对应的项目实现：命令引擎、语法分析……"，点得过去
- [ ] 打开命令引擎讲解页，能看到"读懂这里需要先学：CS61A、CS143……"，点得过去
- [ ] 这些链接**是自动生成的**，不是手写死的——改注释里的 `@courses`，链接跟着变

### 步骤 5.4　按课程反查的命令

**验收清单**
- [ ] 输入课程名，列出学完它之后可以读的所有模块
- [ ] 输入模块名，列出读懂它需要先学的课
- [ ] 输出每一项可以点

**验收清单**

**验收清单**

- [ ] 清空浏览器数据后，导入那个文件，心得全部回来
- [ ] 导出的文件用记事本打开是能读的（不是乱码）

**验收清单**
- [ ] 作者的心得写在内容文件里，跟项目走
- [ ] 任何人打开都能看到，且和访问者自己的心得在视觉上分得清

### 步骤 6.4　公开评论（Giscus）

**验收清单**
- [ ] 页面底部有评论区，用 GitHub 账号能登录
- [ ] 发一条评论，去仓库的 Discussions 里能看到它

## 阶段 7：内容填充（持续进行，不算"一次 coding"）

**目标**：把 csdiy.wiki 的课程树补全。

这是内容工作不是编码工作，可以让 AI 批量帮忙生成课程页骨架，但**每一门都要你自己过一眼**。

**验收标准**（每批）
- [ ] 链接都点得开
- [ ] 没有自编习题
- [ ] 分类正确，同类课程并列摆放
- [ ] 侧边栏没有因为条目变多而变得没法用

## 阶段 8：进度与理解度（约 3 次 coding）

### 步骤 8.1　访问者的学习状态

**验收清单**
- [ ] 能把一门课标成"想学 / 在学 / 学完"
- [ ] 命令行里也能标、也能查
- [ ] 刷新后还在，导出功能包含这些数据

### 步骤 8.2　理解度（教材的第二条进度线）

**验收清单**
- [ ] 每个代码模块能标"未读 / 读过 / 读懂了"
- [ ] 有个地方能看到整体理解度百分比
- [ ] 这个百分比是**读者自己的**，不是作者的

### 步骤 8.3　作者的进度

**验收清单**
- [ ] 作者进度写在内容文件里，人人可见
- [ ] 和访问者自己的进度**显示上分得清、数据上完全独立**
- [ ] 访问者清空自己的数据，作者的进度不受影响（**这条一定要试**）

## 阶段 9：自定义学习路径（约 3 次 coding）

**目标**：使用者能在课程树上自己组一条路线。

**验收清单**
- [ ] 能新建一条路径，往里加课程、排顺序、删除
- [ ] 能同时存在多条路径，能切换
- [ ] 一门课能同时属于多条路径
- [ ] 路径存在访问者本地，导出功能包含它
- [ ] 作者那条 learncs.site 路线作为**示例**存在，可以一键复制成自己的
- [ ] 项目内容里**没有把任何一条路线的顺序写死**

## 阶段 10：命令进阶（约 4～5 次 coding）

### 步骤 10.1　`tree` `pwd` `history` `clear`
- [ ] 行为和真 Unix 一致
- [ ] `tree` 的输出能折叠

### 步骤 10.2　Tab 补全
- [ ] 打一半按 Tab 能补全命令名和路径
- [ ] 多个候选时列出来，不自作主张选一个

### 步骤 10.3　`find` 和 `grep`
- [ ] `find` 能按条件筛课程（分类、状态、先修）
- [ ] `grep` 能过滤结果

### 步骤 10.4　管道
- [ ] `find ... | grep ...` 能用
- [ ] 让 AI 确认：**命令之间传的是结构化数据，不是文本**
- [ ] 三个命令串起来也能用

**这一阶段是"终端能做而鼠标做不到"的兑现。**做完之后回头看阶段 4 的疑问：
现在终端好用了吗？

## 阶段 14：美化（约 3～4 次 coding）

**到这一步才允许碰外观。**

- [ ] 手机上真的好用（不只是"能打开"）

## 阶段 15：开源打磨 → **1.0**（约 3～4 次 coding）

- [ ] README 写清楚：这是什么、为什么这样设计、怎么用、在线地址
- [ ] README 里说清"课程是目录、代码是正文、习题用官方的"这个核心设定
- [ ] 有贡献指南，说明别人怎么补课程、怎么改注释
- [ ] 有 LICENSE
- [ ] 提交代码时自动跑检查
- [ ] **找一个不认识的人打开网站，看他十分钟内能不能搞懂这是什么**

### 🏁 1.0 的标准

- [ ] 课程树覆盖 csdiy.wiki 的主要分支
- [ ] 每个核心模块都有讲解页和完整的 `@letter` 注释
- [ ] 课程 ↔ 代码双向跳转全线打通
- [ ] 心得可写、可导出、可公开
- [ ] 使用者能自建学习路径
- [ ] 终端够好用，你自己会主动去敲
- [ ] 别人 fork 走能直接开始学、开始写自己的心得
